# Image-description services

Research date: 2026-10-16

This note is implementation research. It is not part of the end-user guide and is excluded from the release PDF.

This document surveys services that can generate a natural-language description from a postcard image. Prices, quotas, model names, and privacy terms change frequently; verify the linked official documentation before implementation.

## Summary

There is no reliable, permanently free public API that works anonymously and is suitable as a production dependency.

Practical options are:

1. **Self-hosted Ollama** for privacy and no per-request fees.
2. **Google Gemini API** for a limited free prototype or a very inexpensive paid service.
3. **Anthropic Claude or OpenAI vision-capable models** as paid alternatives.

For private postcards, local inference should be the default. Any cloud-generated description should be presented as an editable suggestion, never stored without user review.

## Free and free-tier options

### Google Gemini API free tier

Gemini can accept an image and return a freely prompted natural-language description through REST APIs and SDKs.

- Requires a Google account and API key.
- Selected Flash and Flash-Lite models have a free tier.
- Concrete request and token quotas are project-specific, visible in Google AI Studio, and not guaranteed.
- Google's pricing table states that free-tier content may be used to improve its products. This makes the free tier unsuitable for postcards containing private messages, names, or addresses.
- The paid tier states that submitted content is not used for product improvement.

Official documentation:

- [Gemini API pricing](https://ai.google.dev/gemini-api/docs/pricing)
- [Gemini API rate limits](https://ai.google.dev/gemini-api/docs/rate-limits)
- [Gemini image understanding](https://ai.google.dev/gemini-api/docs/image-understanding)

Verdict: useful for prototypes with non-sensitive images; use a paid tier for real private collections.

### Azure AI Vision Image Analysis

Azure AI Vision offers a caption feature that returns a short image description.

- The F0 tier advertises up to 5,000 transactions per month and 20 transactions per minute.
- Requires an Azure account/subscription; payment-card requirements depend on the signup path and were not conclusively verified.
- Captions are less flexible than descriptions generated by a general vision-language model.
- Output-language quality, especially German output, should be tested with actual postcards before selection.

Official documentation:

- [Azure AI Vision pricing](https://azure.microsoft.com/en-us/pricing/details/cognitive-services/computer-vision/)

Verdict: a viable free quota for short captions, but less flexible than a multimodal language model.

### Google Cloud Vision

Google Cloud Vision offers a limited monthly free allowance for features such as label and text detection. The first 1,000 units per month are listed as free; billing must generally be enabled for Google Cloud use.

Official documentation:

- [Google Cloud Vision pricing](https://cloud.google.com/vision/pricing)

This is not a direct substitute for a fluent image description. It is useful for OCR, object labels, and metadata extraction.

### Hugging Face Inference Providers

Free Hugging Face accounts currently receive no monthly inference credit. PRO, Team, and Enterprise plans include limited compute credits, and additional use is pay-as-you-go.

Official documentation:

- [Inference Providers pricing](https://huggingface.co/docs/inference-providers/pricing)
- [Image-to-text providers and models](https://huggingface.co/docs/inference-providers/tasks/image-text-to-text)

Verdict: useful as a single API across multiple providers, but not an always-free service.

### Public demos and playgrounds

Public Hugging Face Spaces and vendor playgrounds may be free to try, but they are not suitable as an application backend. Availability, rate limits, privacy, API stability, and continued operation are not guaranteed.

## Self-hosted option: Ollama

A local multimodal model avoids external image transfer and per-request charges. The remaining costs are hardware, memory, electricity, and processing time.

Candidate models include:

- [Gemma 3](https://ollama.com/library/gemma3), with multimodal variants at 4B, 12B, and 27B parameters
- [Qwen3-VL](https://ollama.com/library/qwen3-vl)

Gemma 3 requires Ollama 0.6 or later. A 4B quantized model is a reasonable first test on a computer with 8–16 GB unified memory, but actual speed and quality must be measured on the deployment hardware. Larger models generally improve detail recognition but require more memory.

Typical local integration:

```text
POST http://localhost:11434/api/chat
```

The request contains the image and a prompt asking for a concise description in the desired language. Review model-specific licensing before distribution or commercial use; for Gemma, see the [Gemma terms](https://ai.google.dev/gemma/terms).

Verdict: preferred default for private collections.

## Popular paid services

### Google Gemini paid tier

Gemini Flash and Flash-Lite models are designed for inexpensive multimodal processing. Exact prices vary by model and may change. For a short description of one postcard, the cost is normally far below one US cent.

Advantages:

- Low cost
- Multilingual output
- Straightforward image input
- Paid-tier privacy terms are more appropriate than the free tier

See [Gemini API pricing](https://ai.google.dev/gemini-api/docs/pricing).

### Anthropic Claude

Claude's vision-capable models accept images and can generate controlled, multilingual descriptions. Billing is based on input and output tokens; an image is converted into image tokens according to its dimensions.

Official documentation:

- [Claude API pricing](https://platform.claude.com/docs/en/about-claude/pricing)
- [Claude vision guide](https://platform.claude.com/docs/en/build-with-claude/vision)

Small/fast models are appropriate for this use case. Stronger models may produce richer descriptions but cost more. Even then, a short description should normally remain well below one cent per postcard.

### OpenAI

Vision-capable OpenAI models can produce freely prompted, multilingual descriptions. Cost depends on the chosen model, image tokenization/detail level, prompt length, and output length.

Official documentation:

- [OpenAI API pricing](https://developers.openai.com/api/docs/pricing)
- [OpenAI vision guide](https://developers.openai.com/api/docs/guides/images-vision)

Model names and pricing change frequently, so choose a current vision-capable mini or nano model during implementation rather than hard-coding a recommendation from this research date.

### Other established paid routes

- [AWS Bedrock](https://aws.amazon.com/bedrock/pricing/) provides managed access to Claude and other multimodal models.
- Azure OpenAI provides OpenAI models through Azure and may be preferable for existing Azure governance and regional requirements.
- Google Vertex AI provides Gemini through Google Cloud with enterprise controls.
- [Replicate](https://replicate.com/pricing) hosts many open-source vision models, usually billing by hardware runtime.
- Hugging Face Inference Providers routes requests to multiple providers with consolidated billing.

## Label APIs are not captioning models

Classical computer-vision APIs usually return labels, OCR text, objects, landmarks, or faces. Those results are valuable for tags and transcription, but they do not replace a fluent description.

For example:

- Label API: `mountain`, `lake`, `postcard`, `building`
- OCR: an exact attempt to transcribe handwriting or printed text
- Vision-language model: “A historic lakeside town beneath snow-covered mountains, viewed from the water.”

A useful postcard workflow may combine OCR with a vision-language-model description.

## Recommendation for this project

### Provider architecture

Implement image descriptions behind an optional provider interface rather than coupling the application to one vendor:

```text
disabled
ollama
gemini
anthropic
openai
```

Secrets must remain outside exports, logs, the database, and the repository. Cloud calls should be opt-in and clearly state that the image leaves the local system.

### Recommended order

1. Prototype **Ollama with Gemma 3 4B** locally.
2. Evaluate 10–20 representative postcard fronts and backs, including small print, handwriting, stamps, historical scenes, and ambiguous locations.
3. Add **Gemini paid** as an optional cloud provider if local quality or speed is insufficient.
4. Keep Claude or OpenAI as interchangeable alternatives.

### Product behavior

- Generate a description only on explicit user action.
- Display the result as an editable suggestion.
- Never infer or persist a location or year as fact without confirmation.
- Provide separate actions/prompts for front-side scene description and back-side OCR/transcription.
- Record which provider/model created a suggestion only if this can be done without exposing secrets or unnecessary operational details.

## Cost expectations

For inexpensive cloud models, a short caption usually costs a small fraction of one US cent. A collection of 1,000 postcards will commonly cost less than one US dollar, but image resolution, token accounting, prompt size, response length, and model choice can materially change that estimate.

Run a small benchmark against current pricing before implementation. Quality, privacy, and predictable availability matter more than the raw API cost at this project scale.

## Open questions before implementation

- Which deployment hardware will run Ollama, and how much RAM/VRAM is available?
- Should descriptions cover only the postcard front, or also summarize/transcribe the back?
- Must all processing remain local?
- Which languages should be generated automatically?
- Is a provider-specific API key acceptable, and how will it be configured securely?
- Should generated text be stored immediately, or only after explicit confirmation?
- What timeout, retry, file-size, and rate limits should apply?

## Research limitations

- Free-tier quotas can be account-specific and may not be published as fixed numbers.
- Cloud pricing and model availability change frequently.
- No quality comparison was performed with real postcard images.
- Azure payment-card requirements and German caption quality were not conclusively verified.
- OpenAI image-token costs were not calculated for a specific current model.
- Local Ollama hardware recommendations are estimates, not benchmarks on the target host.
